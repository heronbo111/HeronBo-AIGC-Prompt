# 程序 ↔ agent 联调协议

适用对象：`tools\dist\score-tool.exe`（下称"程序"）与调用本 skill 的 agent。

## 0. 一句话

**项目文件夹就是接口。** 程序与 agent 都不直接调对方，各自读写同一个项目目录；
谁先起来谁读盘，所以两边不需要同时在线，也不会丢件。

## 1. 目录约定（程序建，双方读写）

```
<样本库根>/<项目名>/
├── 文案/            用户给的需求 + agent 出的稿子（口播稿.txt / 提示词.txt）
├── 素材/            用户给的素材（程序自动判角色）
├── 即梦上传/        agent 加工的待上传副本（文件名 = 引用编号+角色+时长）+ 上传说明.txt
├── 成片/            程序接收的可用成片
├── 废片/            程序接收的作废抽卡（文件名 = 日期-废因.mp4）
├── 评价/            六维评分 json（评分工具产出）
├── 备注/            主观备注 + 生成参数
├── 框架.json        机器读：素材清单 / 提示词 / 成片记录 / 评价引用
├── 框架.md          人读摘要（自动生成）
└── _会话/           ★ 程序与 agent 的信箱 ★
    ├── 状态.json    程序写：阶段 / 轮次 / exe 是否在线 / agent 会话 id / 待办数
    ├── 待办.jsonl   程序写 → agent 读：用户的反馈与请求（处理完标 done）
    ├── 回执.jsonl   agent 写 → 程序读：这次做了什么、产出了哪些文件
    └── 轮次/001-反馈.txt   每轮反馈原文留档（agent 复盘用）
```

## 2. 状态字段（`_会话/状态.json`）

| 字段 | 谁写 | 含义 |
|---|---|---|
| `stage` | 程序 | `新建 / 等素材 / 等提示词 / 等成片 / 等反馈 / 已完成` |
| `round` | 程序 | 第几轮（每次提交反馈 +1） |
| `pending` | 程序 | 未处理待办数 |
| `exeAlive` | 程序 | 程序此刻是否在运行 |
| `agentSession` | 程序 | **钉住的 agent 会话 id**（见第 4 节） |
| `generated` / `lastVerdict` | 程序 | 已接收成片数 / 最近一次接收的判定 |

## 3. 待办与回执（JSONL，一行一条）

待办（程序 → agent）：

```json
{"i":1,"at":"2026-09-15T09:33:30","kind":"反馈","text":"结尾三秒画面糊","files":[],"by":"user","status":"open"}
```

`kind`：`反馈`（按反馈再出一版）/ `出提示词`（首次出）/ `归位` / `其它`。

回执（agent → 程序）：

```json
{"i":1,"at":"2026-09-15T09:41:02","kind":"出提示词","text":"已按反馈重切段","files":["文案/提示词.txt","即梦上传/图片1_形象参考_老师.png"]}
```

命令行读写（不给参数就是读）：

```bash
python tools\project_core.py --project "<项目>" --todos           # 读未处理待办
python tools\project_core.py --project "<项目>" --todo-done        # 全部标 done
python tools\project_core.py --project "<项目>" --receipt "做了啥" --receipt-files a.txt b.txt
python tools\project_core.py --project "<项目>" --state           # 看状态
```

## 4. 程序怎么叫 agent（已实测可用）

`tools\agent_bridge.py` 封装了 WorkBuddy 的 headless CLI：

```bash
python tools\agent_bridge.py "只回复 OK"        # 自检通道
```

```python
from agent_bridge import ask, available
ok, why = available()
if ok:
    res = ask("按 _会话/待办.jsonl 里的反馈再出一版提示词",
              session_id="<项目里存的 agentSession>", cwd="<项目>", timeout=900)
    # res = {ok, session_id, text, res(含 duration_ms/num_turns/total_cost_usd)}
```

**⚠️ 必须知道的坑**：CLI 要绑一个本机控制端口，默认与桌面端同为 `7632`，
桌面端开着时会 `listen EADDRINUSE` → **进程静默卡死、零输出**。
`agent_bridge` 已自动注入空闲端口（`SERVER__PORT` / `CLAUDE_CODE_SSE_PORT`），别绕过它自己拼命令。

**会话钉在项目上**：第一次调用不带 `-c/-r`，从返回 JSON 里取 `session_id` 存进
`状态.json` 的 `agentSession`；以后都用 `-r <id>`。
**绝不用 `-c`**——它续的是"最近一个会话"，会把用户正在桌面端聊的那个对话带偏。

## 5. 全流程（谁在哪一步做什么）

| # | 谁 | 动作 | 落盘 |
|---|---|---|---|
| 1 | 用户 | 开新项目、丢需求与素材 | 程序自动建 8 个业务目录 + `_会话/`，自动起名、自动判角色 |
| 2 | agent | 扫 `框架.json` + `文案/` + `素材/`，出提示词 | `框架.json` 的 `prompts`、`文案/提示词.txt` |
| 3 | agent | 加工待上传副本 | `即梦上传/`（引用编号+角色+时长）+ `上传说明.txt` |
| 4 | agent | **起程序**（见第 6 节） | — |
| 5 | 用户 | 在程序里读/复制提示词，去平台生成 | — |
| 6 | 用户 | 把成片/废片丢给程序 | `成片/`、`废片/`（废片自动命名） |
| 7 | 程序 | 接收完 → 弹反馈窗口（可 × 关） | 用户提交后 → `待办.jsonl` + `轮次/NNN-反馈.txt` |
| 8 | 程序 | 点「提交并让 agent 再出一版」→ 调 headless CLI | agent 回到第 2 步，出下一版 |
| 9 | agent | 处理完写回执、把待办标 done | `回执.jsonl`、`待办.jsonl` 状态 |
| 10 | 用户 | 打分（评分工具第四栏 / 程序） | `评价/*.json` |
| 11 | agent | 回收评价 → 改规则 | `rules.md` / `eval-cases.md` / `samples-db.md` |

## 6. agent 侧硬性要求

- **提示词出完必须起程序**：`tools\dist\score-tool.exe --project "<项目>"`。
  程序是单实例：已在跑就把它提到前台并切到该项目，没跑就新开。**不许只在回复里说"请打开工具"。**
- **出完提示词先扫一遍 `_会话/待办.jsonl`**：有 open 的反馈，就是用户又要改一版，先处理再交付。
- **处理完写回执**（哪怕只是一句话），并把对应待办标 done——否则界面上会一直挂着"待办 N"。
- 用户反馈的原文在 `_会话/轮次/*-反馈.txt`，**不要只信对话里的转述**。
- 程序可能被用户随时关掉；**关掉不等于流程结束**，状态都在盘上，下次起来接着读。

## 7. 已知边界（别承诺做不到的事）

- **拖拽**：**已可用**（2026-09-15 修通）。`tools\_vendor\tkinterdnd2` 随仓库分发，程序启动时把
  **整棵控件树**登记为投放目标（约 133 个点），从资源管理器拖文件到窗口任何位置都进「投放台」。
  两个坑记在这里，改这块代码前先看：
  ① tkdnd **只认鼠标正下方那个控件**——只登记顶层窗口时，拖到四栏工作台的子控件上会被拒收；
  ② 必须用 `dnd_bind()` 绑 DnD 事件，普通 `bind()` 会按 tkinter 标准字段去取 `%#` 而抛 TclError
  （回调进不去），且 `<<Drop>>` 回调要**返回动作**（`COPY`），不返回会被系统拒收。
  自检：`dist\score-tool.exe --dnd-selftest`（打印并落盘 JSON：tkdnd 版本 / 投放点数 / 回调是否被调用）。
- **程序不会主动找 agent**：只能 agent 被调用时读待办，或用户在程序里点按钮触发一次 CLI 调用。
  没有常驻守护，也不会后台轮询。
- **一次 CLI 调用 = 一次真实消耗**（`total_cost_usd` 会记在回执里）。
- 程序不代提交生成、不消耗平台积分；只做本地文件与提示词。
- **协议自检**：改完协议相关代码跑 `python tools\联调自检.py`（34 项断言，全过才提交）。
