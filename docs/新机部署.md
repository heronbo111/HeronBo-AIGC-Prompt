# 新机部署（自包含 · agent 照这个跑）

> 2026-09-16 写。起因：别人在另一台电脑上按 README 装完，遇到四个问题——
> ①装得慢（一次拉几百 MB）②装完工作台不弹出来、桌面没快捷方式 ③WebView2 运行库坏了导致
> 工作台窗口**一片空白** ④agent 通道接不上（ZCode 装在多层目录里、机器上没有 Node.js）。
> 本文是修完之后的部署口径；照它做能在 2–5 分钟内到位。

## 0. 一句话

**普通用户：到 Release 下载最新完整安装包，双击即装**（Python/Node/ffmpeg/深度模型/转写和全部依赖
都封在里面，离线可用，不需要 Python/Git）：https://github.com/heronbo111/HeronBo-AIGC-Prompt/releases/latest
（v0.4.3 起 tag 固定为 `vX.Y.Z`，`releases/latest` 永远指向最新版）

**开发者（从源码）：clone（用 `--depth 1`）→ 双击 `一键安装.cmd`（或跑 `python tools\部署.py all --yes`，
依赖联网装）→ 工作台自己弹出来。** 接 agent 通道是**可选**的：哪台电脑装了哪个 agent 就用哪个；
一个都没有时，除「出提示词」外的流程照样能跑。

**agent 看到这行请按场景选节执行**：新机要装技能 + 搭桥 → 只有豆包工作走 **5.6**（装技能+搭桥一步到位）；
有 WorkBuddy/ZCode/Codex 或要多通道 → 走 **5.5**。

## 1. clone（别把历史一起拖下来）

```bash
git clone --depth 1 https://gitee.com/HeronBo/HeronBo-AIGC-Prompt.git     # 国内
git clone --depth 1 https://github.com/heronbo111/HeronBo-AIGC-Prompt.git  # GitHub（已公开）
```

**为什么必须 `--depth 1`**：仓库历史里有历代 `tools/dist/score-tool.exe`（每个约 18 MB，30 多个版本），
完整 clone 要下 70 MB+ 的历史，而 `--depth 1` 只取最新一层（约 20 MB）。**"安装花了很长时间"，
一半是这里的钱。** 需要完整历史时再去掉 `--depth 1` 重拉。

放哪儿：`~/.zcode/skills/HeronBo-AIGC-Prompt`（ZCode）· `~/.codex/skills/...`（Codex）·
`~/.dsh/skills/...`（DSH）· 或任意目录（对 agent 说「读 <路径>\SKILL.md 并按其工作流执行」）。

## 1.5 普通用户走完整安装包；公开仓库只有代码（v0.4.0 起）

- **普通用户**：下载 Release 的完整安装包（v0.4.5 起叫 `HeronBo-Workbench-Setup-vX.Y.Z.exe`，约 700MB），
  双击即装、依赖全封装、离线可用；Gitee 因附件 100MB 上限放不了完整包，只放 score-tool 内核。
- **公开 git 仓库只有代码**（clone 约 13MB）：安装资产（ffmpeg / 深度模型 / 重轮子）与 exe
  **不进 git、也不再作为 Release 散装附件**——它们的功能已全部封进完整安装包。
- **开发者从源码装依赖**：`python tools\部署.py all --yes`（联网：找 Python、装依赖、接 agent、建快捷方式、起工作台）；
  重工具（numpy/opencv/faster-whisper/onnxruntime/ffmpeg/深度模型）由 `部署.py` / `环境检查.py` 联网获取。
- **更新工作台**：普通用户在工作台点「检查更新」；开发者重打 exe（见第 7 节）。

**⚠️ 换机 / 老 clone 同步（历史被减重重写过）**：老 clone 直接 `git pull` 可能把本地大件
从工作区删掉（它们不被跟踪）。想保住本地文件，先取消跟踪再拉：

```bash
git rm -r --cached --quiet tools/_vendor/wheels-heavy tools/_vendor/ffmpeg tools/_vendor/models tools/dist/score-tool.exe
git fetch --all && git reset --hard origin/main      # 或干脆重新 clone（只有 13MB）
```

## 2. 一键安装

**双击仓库根目录的 `一键安装.cmd`**（或在终端 `python tools\部署.py all --yes`）。它按顺序做五件事：

| 步骤 | 做什么 | 备注 |
|---|---|---|
| 1 | 找 Python | 找不到会打印下载地址并打开官网；Python ≥3.9，装时勾 "Add to PATH" |
| 2 | 装依赖 | **优先用仓库自带的离线 wheel**（`tools/_vendor/wheels/`，约 4 MB，免联网、几秒装完）|
| 3 | 接 agent 通道 | 探测本机四个 agent，能接的接上，最后真跑一句最小任务验证"装完就能干活" |
| 4 | 建桌面快捷方式 | 有 exe 指向 exe；没有 exe 指向源码启动器（`tools\工作台.py`）|
| 5 | 起工作台 | 独立窗口 → Edge 窗口 → 默认浏览器，三层退路 |

细项命令（都在 `tools\` 下跑）：

```bash
python tools\部署.py check        # 体检：python / tkinter / pywebview / WebView2 / node / ffprobe / exe / 图标 / 样本库根
python tools\部署.py install --yes   # 装必需依赖（离线包优先）；--extras 连可选大包一起装
python tools\部署.py agents --yes    # 接 agent 通道 + 连通测试（--no-ping 跳过真跑）
python tools\部署.py shortcut --yes  # 桌面快捷方式
python tools\部署.py start --yes     # 起工作台
python tools\工作台.py               # 源码方式起工作台（不依赖 exe）
```

## 3. 依赖：普通用户靠完整包；开发者联网装（v0.4.0 起）

- **普通用户什么都不用装**：完整安装包已封入嵌入式 Python、便携 Node、ffmpeg、深度模型、
  faster-whisper 与全部 Python 库，离线机器装完即可跑 ffmpeg / 转写 / 深度视频。
- **开发者从源码**：`python tools\部署.py install --yes` 装必需依赖、`--extras` 连重工具
  （numpy/opencv/faster-whisper/onnxruntime）一起装；ffmpeg 与深度模型由 `部署.py` /
  `环境检查.py`（`--models`）联网获取。装软件前会先征得用户同意。

## 4. 工作台白屏 = WebView2 运行库坏了（**已加自检 + 兜底**）

工作台界面是 pywebview 内嵌 WebView2 渲染的。**坏法很阴**：注册表写着装了某版本，但那个版本目录里
`msedgewebview2.exe` 不见了（`msedge.dll` 还在），于是窗口**开出来是一片空白**，pywebview 的报错在
GUI 线程里被吞掉，程序自己看不出问题。

现在有三道防线：

1. **起窗前预检**（`webview2_state()`）：既查注册表版本，也查那个目录里宿主 exe 在不在。不可用就
   **根本不试独立窗口**，直接退 Edge 窗口，并打印修复步骤（不会让你对着白窗发呆）。
2. **白窗看门狗**：页面 25 秒没连上来（静态页/心跳都没到）→ 认定白窗，关掉它、退 Edge，并写
   `%TEMP%\heronbo_webview2.txt`。
3. **自检项**：`python tools\部署.py check` 里有一行「WebView2 运行库」；坏了会打印修法。

修（一条命令，微软官方引导器，装前会校验签名）：

```bash
python tools\部署.py wx --yes        # 下载 + 静默安装 Evergreen WebView2 Runtime
# 手动等价：https://go.microsoft.com/fwlink/p/?LinkId=2124703 → 运行 MicrosoftEdgeWebview2Setup.exe
```

`tools/部署.py fix-webview2 --yes` 与 `wx` 同一条。装完复查一遍 `check`；部分机器要重启一次。
**注意**：WebView2 坏掉不只影响本工作台——本机所有用 WebView2 的程序（Teams / 微信 / 一些 Electron 应用）都会白屏。

## 5. agent 通道：**哪台电脑装了什么就用什么**

工作台不绑定某个 agent，而且**界面上只列这台电脑上真正有的**——别人机器上装了什么，这边不会凭空多出来
（没装的收在「本机没装的（N）」折叠块里，点开能看装法与原因）。探测顺序与优先级：

1. 你在界面里点过一行 → 就用它（配置存 `tools/agent_bridge.local.json`，打包后＝exe 旁边）；
2. 没点过 → **跟随你正开着的客户端**（前台那个优先）；
3. 都没开 → 用「把本技能装在自己名下且命令行可用」的那个；
4. 都没有 → 只有需要模型的按钮变灰，其余照常。

**没有 Node.js 也能接**（2026-09-16 修，另一台机器就卡在这里）：

| Agent | 需要什么 | 没有 node 时 |
|---|---|---|
| WorkBuddy | `WorkBuddy\resources\app.asar.unpacked\cli\dist\codebuddy-headless.js` | 用 **WorkBuddy 自带的 Electron** 当 node 跑（`ELECTRON_RUN_AS_NODE=1`）|
| ZCode | `resources\glm\zcode.cjs`（**多层目录也找得到**，如 `F:\新建文件夹 (3)\ZCode\...`）+ `~/.zcode/cli/config.json` 里有 provider/model | 用 **ZCode.exe** 当 node 跑（同样机制）|
| Claude Code | `claude`（npm 全局 / `~/.local/bin` / `~/.claude\local`）| 必须装 Node.js（或官方 native 安装）|
| Codex CLI | `codex`（npm 全局）| 必须装 Node.js |
| DSH | `@deepseek-ai/dsh`（npx 缓存或全局）| 必须装 Node.js |
| 豆包工作（企业版）| 官方桌面端 `DoubaoWork.exe`（**没有 CLI**）+ `tools\doubao_cdp.mjs` 桥 | 桥要一个 node；没有独立 node 时**借 WorkBuddy/ZCode 的 Electron** 跑；接管前客户端必须是**带调试端口起的**那份（见 `tools\doubao_cdp.mjs` 顶部说明）|

ZCode 的新机常见两步：`zcode login --no-browser`（浏览器授权）→ 若账号没额度，`python tools\部署.py agents --yes`
会试着把桌面端可用的 provider 并进 CLI 配置（**改前备份**；涉及带 key 的配置，需用户同意）。

### 5.5 搭桥任务提示词（复制给本机 agent 照做）

> 2026-09-30 加。起因：新机上只对 agent 说"装这个 skill 并和本机工作台搭桥"，它根本不知道要做什么
> （实测豆包收到后无从下手）。正确姿势是把下面**整段**复制给它——工作台「agent 通道」弹窗
> （零可用时）也有「复制搭桥任务」按钮，内容同源、且带本机真实配置文件路径。

```text
【任务】把 HeronBo 视频工作台与本机 agent 通道搭桥（照以下步骤做，不要自由发挥）

背景：工作台是本机已安装的桌面程序，「出提示词 / 按反馈重出 / 核对归类 / 评价反哺」
需要一个能被无头调用的 agent；技能 HeronBo-AIGC-Prompt 负责提示词方法论。
搭桥 = 让工作台探测到并调得动本机 agent。

1. 用对工作台 exe：只认安装副本（%LOCALAPPDATA%\Programs\HeronBo\ 下、桌面快捷方式指向的
   那份）；不要跑代码仓库 tools\dist 里的旧 exe（界面右上角「构建」日期早于 2026-09-30 就是旧的）。
2. 探测本机能当通道的 agent，有谁用谁：
   · WorkBuddy 桌面端（首选）：CLI 自带，没有 Node.js 也能跑（借它自带的 Electron）；
   · ZCode 桌面端：CLI 自带（resources\glm\zcode.cjs）；首次用前确认 ~/.zcode/cli/config.json 已配 provider；
   · 豆包工作（DoubaoWork 企业版）：无 CLI，工作台 v0.4.3+ 通过调试端口接管（接管前先退出它，
     或用 tools\doubao_cdp.mjs restart --yes 让它带端口重启）；
   · Claude Code / Codex CLI / DSH：各自 CLI + Node.js。
   注意：个人版豆包没有无头通道，工作台接不了它。一个都没有 → 装 WorkBuddy 或 ZCode 桌面端（最省事）。
3. 把技能装到该 agent 名下：整个技能目录（HeronBo-AIGC-Prompt）放进它的用户级技能目录：
   WorkBuddy → ~/.workbuddy/skills/；ZCode → ~/.zcode/skills/；Codex → ~/.codex/skills/。
4. 固定通道（可选）：在工作台 exe 同目录的 agent_bridge.local.json 里写 {"agent":"workbuddy"}；
   自定义命令行通道：{"agents":[{"key":"myagent","label":"我的agent","cmd":["myagent","-p","{prompt}"],"cmd_mode":"text"}]}
5. 验证：重开工作台「agent 通道」弹窗 → 该通道点「测一下」显示通了；
   或跑 python tools\deploy.py agents --yes 连通测试。完成后回复「搭桥完成 + 用的哪个通道」。
```

### 5.6 豆包工作-only 新机：装技能 + 搭桥一步到位

> 2026-09-30 加。场景：**新机上只装了豆包工作**（没有 WorkBuddy/ZCode/Node.js）。
> 用户只丢一句仓库链接（如「读 https://github.com/heronbo111/HeronBo-AIGC-Prompt 并照 docs/新机部署.md 做」）
> 时，agent 应走到这一节、把下面整段当任务书执行。
> 与 5.5 的区别：不需要装任何运行环境（安装包自带便携 Node），搭桥方式是**退出豆包工作 →
> 工作台启动器带调试端口重拉它**（CDP 接管），技能无需装到豆包名下（安装目录自带一份）。

```text
【任务】安装 HeronBo-AIGC-Prompt 技能，并与本机已装的 HeronBo Workbench 搭桥
（严格照以下步骤做，不要自由发挥，不要装任何额外软件）

第 1 步 · 认对工作台
工作台（v0.4.5+，应用名叫 HeronBo Workbench）装没装、装在哪，**不要猜路径**：
右键桌面快捷方式「HeronBo Workbench」→ 属性 →「目标」，即 <安装目录>\HeronBo.exe；
或查注册表 HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\ 下 HeronBo 的
InstallLocation。解析不到 → 本机还没装工作台：请用户先到
https://github.com/heronbo111/HeronBo-AIGC-Prompt/releases/latest 下载
HeronBo-Workbench-Setup 装好，再回来继续。
下文 <安装目录> 都指这个目录。界面右上角「构建」日期早于 2026-09-30 的 exe 是旧版，不能用；
也不要去跑任何代码仓库 tools\dist 里的 exe。

第 2 步 · 安装技能
git clone --depth 1 https://github.com/heronbo111/HeronBo-AIGC-Prompt.git
放到 C:\Users\<用户名>\HeronBo-AIGC-Prompt。
注意：工作台安装目录里自带一份技能（<安装目录>\skill\），克隆的这份只是你的
方法论参考，不要用它覆盖安装目录里的任何文件。

第 3 步 · 搭桥（核心，不需要 npm install、不需要装 Node.js）
搭桥 = 让工作台能通过调试端口接管你（豆包工作）。做法：
a. 把豆包工作完全退出（包括托盘图标）；
b. 双击桌面「HeronBo Workbench」——启动器会自动带调试端口重启豆包工作并接桥；
c. 在工作台 exe 同目录（<安装目录>\skill\tools\dist\）创建 agent_bridge.local.json，
   内容只写一行：{"agent":"doubaowork"}
   （注意是 dist 目录、exe 旁边，不是 skill\tools\ 本身。）
d. 验证：用工作台自带的便携 Node 跑（一行命令）：
   "<安装目录>\runtime\node\node.exe" "<安装目录>\skill\tools\doubao_cdp.mjs" status
   预期：能认出豆包工作客户端、打印会话目录、探针显示可用。
   （也可以在工作台「agent 通道」弹窗对豆包工作通道点「测一下」，显示通了才算数。）

   ⚠️ **如果 status 说"没找到 DoubaoWork.exe"**（豆包工作装在非默认位置时的死环：
   启动器找不到它、你又不能重启自己）——你能自己破环，三选一：
   ① 把你的 DoubaoWork.exe 完整路径合并写进 agent_bridge.local.json（新增
      "doubaowork": "D:\\...\\DoubaoWork.exe" 字段，保留原有 agent 字段）；
   ② 执行 setx HERONBO_DOUBAO_EXE "D:\\...\\DoubaoWork.exe"（新装版本即支持）；
   ③ 都不行就提示用户用 --exe 参数。
   写完提示用户：完全退出豆包工作 → 双击桌面「HeronBo Workbench」→ 回本会话重跑 status。

第 4 步 · 回报
回复「搭桥完成」并贴出 status 的完整输出。如果报错，原样贴报错，
不要自行改配置、不要重装任何东西、不要另起第二个豆包工作实例。
```

**注意**：个人版豆包（网页/普通客户端）没有调试端口，此路不通——它装得再多也接不了桥。

## 6. 三种启动方式（都在仓库里，随你）

| 方式 | 命令/入口 | 说明 |
|---|---|---|
| 桌面快捷方式 | 双击「HeronBo 视频工作台」 | 指向 exe（有）或 `tools\工作台.py`（没有）|
| 源码 | `python tools\工作台.py [--project X] [--port 8799] [--edge]` | 不用 exe；改完代码立即生效 |
| 只起服务 | `$env:HERONBO_NO_WINDOW=1; python tools\工作台.py --port 8799` | 给别的程序用 API 驱动，不开窗口 |

关窗＝退出（页面心跳停 25 秒后服务自退，不留孤儿进程）。`HERONBO_NO_REUSE=1` 强制再起一个（排查用，
但要给它一个隔离的 `LOCALAPPDATA`，否则两个实例会抢同一个 WebView2 数据目录）。

## 7. 在新电脑上继续改工作台（改 → 打包 → 换位 → 分发）

**先回答最常问的**：**源码在仓库里，exe 不在。**

| | 内容 |
|---|---|
| **在仓库** | `tools/workbench/*`（界面：index.html / app.css / app.js / shell.css / shell.js / flow.*）、`tools/workbench_server.py`（本地服务：接口 · 进度 · agent 调用）、`tools/score_gui.pyw`（经典 Tk 界面）、`tools/agent_bridge.py`（agent 通道）、`tools/score-tool.spec` 与 `tools/build_exe.cmd`（打包配置）、`tools/工作台.ico`（图标） |
| **不在仓库** | 打出来的 `dist\score-tool.exe`、ffmpeg / 深度模型 / 重轮子 → 普通用户用 Release 的**完整安装包**（已全封）；开发者按 7.1 联网准备 |

### 7.1 新电脑的一次性准备

1. 装 **Python 3.12** —— 安装时**勾上 `tcl/tk and IDLE`**（没有 tkinter 打出来的 exe 一启动就崩）
2. `git clone --depth 1 https://gitee.com/HeronBo/HeronBo-AIGC-Prompt.git`
3. `python tools\部署.py check` —— 先看缺什么
4. `python tools\部署.py install --extras --yes` —— 联网装重工具与 ffmpeg/模型（**只改界面可以跳过**，界面不依赖它）
5. `python tools\部署.py install --yes` —— 装必需依赖（仓库带离线轮子，几秒）
6. `python -m pip install pyinstaller` —— 打包器

### 7.2 源码地图（改哪儿）

| 想改什么 | 改哪个文件 |
|---|---|
| 界面布局 / 文案 / 颜色 | `tools/workbench/index.html`、`app.css`、`shell.css` |
| 界面逻辑（按钮、评分表单、进度区…） | `tools/workbench/app.js` |
| 外壳（侧栏、标题栏、窗口拖动、极简模式） | `tools/workbench/shell.js` |
| 接口与本地服务（`/api/*`、进度、动作流） | `tools/workbench_server.py` |
| agent 开工时收到的指令 | `tools/workbench_server.py` 的 `start_agent()` |
| 评分维度与口径 | `tools/score_core.py`（工作台与经典窗口都从它读） |
| 经典 Tk 界面 | `tools/score_gui.pyw` |

**改完不一定要打包**：用源码跑（`python tools\工作台.py`）时，改界面刷新页面就生效；
只有要发给别人一个单文件 exe 时才需要下面这步。

### 7.3 打包 → 换位 → 分发

```bash
tools\build_exe.cmd        # 推荐：自动挑"带 tkinter"的解释器，并检查 PyInstaller
# 或者手动（在 tools 目录下）：
python -m PyInstaller --noconfirm --distpath _stage --workpath build score-tool.spec
python tools\换exe.py      # 换到 tools\dist\score-tool.exe（自动备份旧版）
python tools\发布exe附件.py  # 要分发给别人时：把新 exe 传到 Release 附件
```

- **`换exe.py` 会拦"工作台还开着"**：exe 被占用时连 `--force` 都换不动（WinError 5），先关掉工作台再跑。
- 桌面快捷方式：`python tools\部署.py shortcut --yes`（会问系统拿**真实**桌面路径，桌面被 OneDrive 重定向也不会建到你找不到的地方）。

## 8. 排错速查

| 现象 | 先看 |
|---|---|
| 双击没反应 / 窗口一片空白 | `python tools\部署.py check` 的 WebView2 行；`%TEMP%\heronbo_webview2.txt` |
| 起不来、有报错 | `%TEMP%\heronbo_webview_error.log` · `%TEMP%\workbench_web_crash.log` |
| 界面「agent 通道不可用」 | `python tools\部署.py agents`（会逐个说明缺什么、怎么补）|
| 装依赖很慢 | 是不是在装 `--extras`（numpy/opencv/转写/深度）；核心包用离线 wheel 是秒级的 |
| 双击 `启动评分工具.bat` 说找不到 python | 刚写进 PATH 而资源管理器没重读环境变量 → 注销重登，或重启 explorer.exe |
| 两台机器想同时开工作台 | 别用同一个 `%LOCALAPPDATA%\HeronBoScoreTool`（WebView2 数据目录冲突）；这也是单实例复用存在的原因 |
