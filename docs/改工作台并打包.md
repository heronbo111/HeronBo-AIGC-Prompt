# 改工作台 → 打包替换（一条命令）

给自己（或任何人）改工作台时看的操作手册。**先记住一件事：改的文件必须落在
`<技能目录>\tools\` 下**——工作台源码真身只有这一份；私有仓库 `HeronBo-Workbench` 里的
是**单向镜像**（`同步.py` 是 tools/ → 私有仓库），改那边既不影响工作台、还会被下次同步覆盖。

- 技能目录（Windows，本机）：`C:\Users\WUKONG\.zcode\skills\HeronBo-AIGC-Prompt\tools\`
- `~\.workbuddy\skills\HeronBo-AIGC-Prompt` 是指向它的 **junction**（同一个目录，开哪个都行）

---

## 一、先分清你改的是哪一类（生效方式完全不同）

| 你改的 | 生效需要 |
| --- | --- |
| `workbench\app.js` / `index.html` / `app.css` / `shell.js`（界面） | 源码跑：**刷新窗口**；exe 跑：**重新打包** |
| `tools\workbench_server.py`（本地服务、阶段名、指令） | 源码跑：**重启**；exe 跑：**重新打包** |
| `references\rules.md`、模板、样本库 | 什么都不用做——agent **每轮从磁盘现读** |
| `tools\*.py` 里的命令行工具（体检、拆解、深度视频…） | 什么都不用做——按路径现调现跑 |

**结论**：只有「界面 + 本地服务」这两块被打包进 exe，改了才需要重打包。

---

## 二、日常调试：用源码跑（改完刷一下就见效，最快）

关掉工作台（下面两个 `score-tool.exe`），用**带 tkinter 的 Python** 从源码起：

```bat
"C:\Users\WUKONG\AppData\Local\Programs\Python\Python312\python.exe" "C:\Users\WUKONG\.zcode\skills\HeronBo-AIGC-Prompt\tools\工作台.py"
```

- 改界面（js/css/html）→ **刷新窗口**（不用重启）
- 改 `workbench_server.py` → **关掉重开**那个源码窗口

> 为什么必须指定解释器：这个 Python 有 tcl/tk。用没 tkinter 的 Python 起会崩。
> 记不住路径也没关系——`tools\build_exe.cmd` 里的挑法（`py -3.12` / `py -3.13` / `py -3`）也能用。

---

## 三、要出"正式版"：一条命令打包 + 换位

改到自己满意后：

```bat
cd C:\Users\WUKONG\.zcode\skills\HeronBo-AIGC-Prompt\tools
python 打包换位.py
```

它会按顺序做完（每步都打印结果）：

1. 看现状：工作台在不在跑、当前 `dist\` 的 exe 是哪个时间/多大；
2. 自动挑「带 tkinter **且**装了 PyInstaller」的解释器（挑错＝exe 一启动就崩）；
3. 按 `score-tool.spec` 打包 → `tools\_stage\score-tool.exe`；
4. **验包**：确认 `workbench\` 前端、`workbench_server.py`、`agent_trace.py`、`提示词体检.py` 都在包里
   （这几样是运行时动态加载的，**漏了不报错、只静默失效**：动作流全空、体检按钮没反应）；
5. 换位到 `tools\dist\score-tool.exe`（桌面快捷方式指的就是它），旧版自动备份成
   `score-tool_旧_<日期时间>.exe`。

**如果工作台正开着**：第 3、4 步照做，第 5 步换位会被挡下（开着换位可能让正在跑的实例莫名崩），
并告诉你下一步怎么做。这时你只要关掉工作台，再跑：

```bat
python 打包换位.py --swap-only
```

### 其它开关

```bat
python 打包换位.py --dry         :: 只体检：看会用哪个解释器、exe 在不在跑、会做什么
python 打包换位.py --build-only  :: 只打包，不碰 dist
python 打包换位.py --kill        :: 允许先结束正在跑的工作台再换位（会丢掉那一轮正在跑的任务）
python 打包换位.py --py "<python.exe>"   :: 指定打包解释器
```

也可以直接**双击 `tools\build_exe.cmd`**（它就是调这个脚本）。

## 四、打包失败/看着成功但不对：对着这张表查

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| `[失败]` + 一堆 ModuleNotFound | 打包解释器没装 PyInstaller | `"<python.exe>" -m pip install pyinstaller` |
| 找不到带 tkinter 的解释器 | 装的 Python 没勾 tcl/tk | 装含 tcl/tk 的 Python 3，或 `--py` 指定 |
| `[停] 换不进去（PermissionError）` | 工作台正开着，exe 被占用 | 关掉它，跑 `--swap-only`；或 `--kill` |
| **打包成功、但界面没有工作台**（或动作流全空、体检没反应） | 用了自己拼参数的旧写法，没走 spec | 只走 `打包换位.py` / `build_exe.cmd`；spec 会把 `datas` 全带上，第 4 步**验包**也会拦住 |
| 改了界面但 exe 里没变 | 只改了源码、没重新打包 | 见第一张表：源码跑刷窗口，exe 跑必须重打包 |
| 改了私有仓库里的副本、没效果 | 那是镜像，方向是 tools/ → 私有仓库 | 改 `tools\` 下的那份 |

打包日志在 `tools\build\打包.log`（不进仓库），失败时脚本会自己打印结尾 30 行。

## 五、让别的机器也拿到这一版

exe **不进 git**（仓库只放代码，否则历史会被撑爆），分发走 GitHub Release 附件：

```bat
python tools\发布exe附件.py          :: 传当前 dist 的 exe 到 Release
```

别的机器上用 `python tools\deploy.py vendor --fetch --yes` 拉（同一个命令也是"更新工作台"）。
**exe 不需要提交**，所以打完包不用为它做任何 git 操作。

## 六、源码不在公开仓库里？

对。工作台源码（`workbench\`、`workbench_server.py`、`工作台.py`、`score-tool.spec`、
`build_exe.cmd`、`打包换位.py`）**不随公开仓库分发**，在私有仓库
`https://gitee.com/HeronBo/HeronBo-Workbench`（需要有权限）。

换一台机器时：

1. `git clone` 私有仓库到任意位置（比如 `<技能目录>\..\HeronBo-Workbench`）；
2. 把里面这几样**拷进** `<技能目录>\tools\` —— 注意这是 `同步.py` 的**反方向**：
   `workbench\`、`workbench_server.py`、`工作台.py`、`score-tool.spec`、`build_exe.cmd`、`打包换位.py`；
3. 那台机器装上「含 tcl/tk 的 Python 3」+ `pyinstaller`，就能 `python tools\打包换位.py` 了。

> ⚠️ 别搞反方向：`同步.py` 只做「技能目录 → 私有仓库」，**不会**把私有仓库的内容倒回 tools/。

没有私有仓库权限时：找维护者要源码 zip（在私有仓库里跑 `python 打包源码.py` 生成，
内含 `还原.py`；解压后跑它即自动回位到 `tools\`）。
