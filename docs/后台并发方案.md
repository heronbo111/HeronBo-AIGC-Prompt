# 后台并发方案（草案，2026-10-16）

> **状态：草案，未实现。** 用户口径：多线程先出方案，不着急做。
> 读完这份要能回答三个问题：为什么现在不能并发、并发卡在哪、分几步放开。

## 一、为什么想做

现状一句话：**整台工作台同一时刻只允许一轮 agent 任务在跑**。第二个任务会被
"上一个项目「X」还在跑"挡回（`_PROG` 是单例，见 `workbench_server.start_agent`）。

带来的卡点：

1. 重活（出提示词、素材识别）一跑几分钟到十几分钟，这期间**别的项目完全动不了**——
   只能干等，或者点「暂停」把当前这轮掐掉；
2. 有些活本来是"轻的"（跑个通道自检、读个信箱、回个评价），却也排在同一条队上；
3. 多项目用户（本机就是：Demo / test1 / test2 …）在多项目间来回切时体感最明显。

## 二、现状盘点（并发必须先绕开的约束）

| 资源 | 现状 | 并发允许度 |
|---|---|---|
| 进度容器 `_PROG` | **单例**：lines / stages / events / running 都是一份 | 必须拆成"每任务一份" |
| 任务闸门 | `start_agent` 里"有任务在跑就挡回"（带判活与自动清账） | 换成队列 + worker |
| 豆包 CDP 通道 | 单客户端、单调试端口、`acquireSession` 锁 target；拉窗口/接管都是全局动作 | **天然串行**：任一时刻只能一个豆包会话 |
| CLI 通道（WorkBuddy / ZCode / Codex / Claude / DSH） | 每次 `ask` 起一个子进程；`child_env` 已给每任务分配独立控制端口 | 可并行（吃 CPU / 内存），但见下 |
| 项目文件 | `框架.json`、`文案/`、`素材/`、回执都是**项目内单份** | **同项目并行＝写冲突**，必须串行 |
| agent 会话 | 按项目 + 通道存（`agentSessions{key: sid}`） | 同项目同通道两个会话并行 → 上下文互相看不见，不建议 |
| 界面 | 一处进度区读 `_PROG`；按钮的可用/禁用都看它 | 要能显示 N 张任务卡 |

结论：**能并发的边界是"不同项目 + 不同（或同一批 CLI）通道"，不能并发的是"同一个项目"与"豆包多条"**。

## 三、方案（分阶段，每阶段独立可用）

### 阶段 1：多任务骨架（不碰 agent 侧）

- `_PROG`（单例）→ `_JOBS`（dict：`job_id → 现有结构 + pdir / what / state`）；
- 新增 `_QUEUE`（FIFO）+ 固定 N 个 worker 线程（N 从 1 开始，行为与现在完全一致）；
- **两级锁**：
  - 项目锁（同一项目同一时刻一轮，保证文件不打架）；
  - 通道锁（豆包全局 1；CLI 各通道独立）；
  - 取任务时两把锁都要拿到才开工，拿不到就等（队列里排着，不失败）。
- 提交入口不变：按钮点了就**入队**，界面立刻出现"排队中"的卡片；
- 任务卡片：进度区从"一条进度"变成"卡片列表"（每卡：项目 / 在做什么 / 步骤点 / 已用时长 / 暂停钮）。

### 阶段 2：按通道分池放开并行

- 池 A：豆包通道（并发度 1，硬约束）；
- 池 B：CLI 通道（并发度默认 2，可配）——两条不同的 CLI 会话同时跑；
- 并发上限在"设置"里给个滑杆（1–3），默认 2；机器吃力时用户能自己压回去。

### 阶段 3：多项目并行体验打磨

- ①栏项目行显示"这个项目有任务在跑"（小转圈）——现在切项目只是切视图，后台本来不断；
- 任务完成：提示音（已有 `heronboChime`）+ 顶部气泡"「test2」的出提示词完成了"；
- 「暂停」语义升级：按任务暂停（现在无参数＝停当前那个）；卡片上各停各的。

## 四、明确不做的

- **同项目并行**：文件写冲突（框架/文案/回执都是单份），收益低、坑深，不做；
- **多开豆包**：单客户端单端口，第二个实例会跟第一个互相踢，不做；
- **任务优先级 / 抢占**：先到先得，谁也别插队——简单、可预期；
- **跨机分布式**：不在本轮讨论范围。

## 五、落地影响面（真做的时候改哪些）

| 文件 | 改动 |
|---|---|
| `tools/workbench_server.py` | `_PROG` → `_JOBS`；`start_agent`（入队）；进度/暂停/停止端点按 job_id；`agent_ok` 的"在跑"判定分任务；`_launch_helper`/更新清理等全局动作要拒绝"还有任务在跑"或排队 |
| `tools/workbench/app.js` | 进度区改卡片列表；轮询/SSE 适配多任务；各按钮禁用条件从"跑没跑"改成"这个项目跑没跑" |
| `tools/agent_bridge.py` | 基本不动（`child_env` 已按任务分配端口）；豆包锁定逻辑保持不变 |
| `docs/` | 本文件随实现更新 |

## 六、风险与验证点

1. **杀软 / 资源**：同时起两个 CLI 会话时的 CPU/内存峰值——阶段 2 实测压一遍（本机 16G 内存跑 2 条没问题，3 条要看）；
2. **日志/记录**：`_会话/agent记录/*.jsonl` 现在按轮追加——并发后要带 job_id（否则两条会话的流混在一个文件里）；
3. **pause / stop**：全局标记 `_STOPPED` / `_PAUSED` 要按任务隔离；
4. **进度区**：卡片多了 UI 会挤——超过 3 张折叠成"N 个任务在跑 ▸ 展开"。
