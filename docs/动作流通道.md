# 动作流通道：让工作台在不同机器上都能看见 agent 在干什么

工作台的「动作流」（进度条下面那条：思考 / 终端 / 读取 / 写入 / 要你确认）不是猜出来的，
它读的是**你正在用的那个 AI 工具自己落盘的会话正文**——就是你在工具界面上看到的过程。
但每家工具把正文放在哪、长什么样都不一样，所以工作台把它做成一张**通道表**：

> 一个通道 = 去哪里找（目录 + 文件名通配） + 按什么格式解析

工作台启动后**只读本机探测到的通道**；探不到的通道自动跳过。
所以「这台机器只装了 WorkBuddy」「那台只装了别的工具」都能各自跑，**不用改代码**。

---

## 一、内置通道（探不到就跳过，互不影响）

| 通道 | 去哪找 | 格式 |
| --- | --- | --- |
| zcode | `~/.zcode/cli/rollout/model-io-*.jsonl` | `zcode` |
| workbuddy | `~/.workbuddy/projects/**/*.jsonl` | `workbuddy` |
| claude | `~/.claude/projects/**/*.jsonl` | `claude` |
| codex | `~/.codex/sessions/**/*.jsonl` | `auto` |
| gemini | `~/.gemini/tmp/**/*.jsonl` | `auto` |
| doubao | `~/.doubao/**/*.jsonl` | `auto` |

`auto` = 按结构猜格式（推荐）。猜测型通道会**逐个文件抽检**：只有

1. 能解析出事件（思考/工具/说明），才把它当正文；目录里无关的 `.jsonl` 会被挡掉。

---

## 二、换机器 / 换工具怎么接上（3 步）

1. **找到那个工具把会话正文写在哪儿**（常见是 `~/.<工具名>/…` 下面的 `.jsonl`）。
2. 照着 `tools/agent_channels.example.json` 复制一份，改名 **`agent_channels.local.json`**，
   填上 `key / label / dir / glob / recursive / fmt`。
3. 把这份文件放到下面任一位置（按优先级）：

   - 环境变量 `HERONBO_AGENT_CHANNELS` 指向的文件；
   - **exe 旁边**（打包版：`tools/dist/`；源码运行：`tools/`）；
   - `~/.heronbo/agent_channels.local.json`。

   重启工作台即可。

`exclude` 可以写 `["claude", "codex"]` 这样，把不想用的内置通道关掉；
同 `key` 可以覆盖内置通道（比如把 `doubao` 的 `dir` 改准）。

---

## 三、自检

```bat
python tools\agent_trace.py --channels     :: 本机探测到哪些通道、各有多少正文
python tools\agent_trace.py                :: 按最新通道打印最近 30 条动作
python tools\agent_trace.py --file X.jsonl :: 指定正文文件看解析结果
```

`--channels` 会顺带列出**配置文件查找位置**，写没写对一眼就知道。

工作台界面上，「现在在做：…」尾巴会显示 **`· 动作流来自 <label>`**，
一眼看出这一轮读的是哪家工具的过程。

---

## 四、读不到正文怎么办

有些工具（或某些版本）**不把过程落盘**，或者落盘位置/格式还没对上。
这时工作台**不会空着**：它会退回解析 agent 自己的输出行（`用 Bash{…}` / `写了 X` / 已读掉…），
照样能看见它在干什么——只是没有图标和耗时那么结构化。

想拿到结构化动作流，就按第二节把那个工具的通道配好。
