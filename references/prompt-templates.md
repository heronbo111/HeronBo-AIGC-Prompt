# 提示词模板（四大类 ↔ 模板）

模板结构来自真实样本与平台 agent 三段式。每个模板给出：框架 + 完整示例 + 注意事项。本文件只供提示词设计，不含 CLI 命令/价格。

## 四大类 ↔ 模板对应表（先定类，再取模板）

| 大类 | 判定信号（用户给什么 / 要什么） | 模板 | 图/视频/音频引用上限 | 关键差异 |
|---|---|---|---|---|
| **图生视频** | 给图（形象图/首帧/尾帧/四视图），无参考视频；要"让它动起来" | **A** 单段 / **B** 多段 / **C2b** 图片驱动双替换 | 只引用真实上传的 @图片 / @音频；**禁止写"参考视频/视频1"** | 图片是唯一锚；道具替换走这条 |
| **文生视频** | 什么都不给，只有一段文字 | **F**（**未验证**） | 无任何 @引用 | 人物/场景/动作/镜头/风格全靠文字；一致性靠描述词逐字复用 |
| **参考视频生视频** | 给参考视频，要"照它的运镜/动作/节奏" | **C**（C1 全片替换 / C1b 两段式 / C2 局部替换） | @视频1 = 动作节奏；可 +@音频（音色参考） | 画面内容自己写，动作节奏跟 @视频1 |
| **参考视频替换生视频** | 给原片 + 要"把里面的人/物换掉" | **C1**（商品拟人化）/ **C2** / **E**（分段多主体） | @视频1 = 原片；+@图片N 替换源 | 锁机位构图与镜头节奏，只换表现层；难度 L1–L4 |
| （音乐二创/翻唱） | 给音乐，要卡点/配口型 | **D**（D1 作曲 / D2 关键帧 / D3 逐段口型） | @图片1 关键帧 +@音频1 音频段 | 参考视频类的特例；声音先行 |

**符号说明**：L1＝物件替换（商品/道具拟人化）、L2＝台词替换（画面全保留）、L3＝同人造型替换（换装/换手中物）、L4＝人物替换进原片（换人并复刻原片动作/镜头/场景）。分级依据与工具选型见 `references/playbooks.md` 第一部分。

## 0. 统一骨架（**出任何提示词前先读这一节**）

> 2026-09-16 用户反馈：同一天两个项目的提示词**小节集合、顺序、交付格式各写各的**——
> 一个项目（口播带货·场景替换）是纯正文 + `【素材分工】【替换】【景别与构图】…`；
> 另一个（剧情演绎·角色替换）是 markdown 报告，正文被包在 `## 二、提示词正文` 里的小节
> `【角色】【场景与站位】【动作与台词】`，还夹着表格与变更记录。用户的原话是
> **"风格不一致的错乱情况"**。同一个 skill 出来的东西必须长得一样——所以骨架**固定**，
> 并且做成了可机器检查的 `tools\提示词体检.py`（本节的检查项与那个工具一一对应）。

**术语（这三个词在本仓库各指一层，别混用——2026-09-16 用户就问过"骨架和框架不是一个东西吗"）**

| 词 | 指什么 | 谁决定 | 例子 |
|---|---|---|---|
| **模板** | 按四大类分的写法包（A/B/C/D/E/F），各带示例 | 本文件 | 替换类取 C1、文生视频取 F |
| **框架** | **某个模板内部的内容提纲**——这一类"每节该写什么"，各类不同 | 各类模板自己（下文 `### 框架` 那几段） | C1 的框架＝主体锚定 + 原片节奏 + 台词插入点 + 音色锚定 |
| **骨架** | **跨类统一的外形**——小节名、小节顺序、交付格式（全类共用一套） | 本节（唯一真相源） | 不管哪一类，正文都是【总纲】→…→【负面】这 11 节 |

一句话：**框架管"写什么"（按类不同），骨架管"长什么样"（所有类一样）**。
出提示词的顺序＝先定类 → 取该类模板/框架想内容 → **套进骨架的小节名与顺序** → 跑
`提示词体检.py` 验外形。**改内容不动骨架；改骨架要同时改本节与 `tools\提示词体检.py` 的 `SECTIONS`。**

### 交付形态：**默认段落式**（2026-09-18 用户裁定，覆盖 2026-09-16 的"骨架式"）

用户 2026-09-18 原话："你的提示词回不到图中这个样子了吗？我的诉求很简单啊，就是现在的提示词太长了"
（给的样例就是他自己一直在用的那条：**括号包起来的一整段**，人物形象→场景→镜头→口播→逐句动作与神态→
禁令，全在一段里，**没有【】小节名**）。所以：

- **正文默认写成一整段**（首尾用（），中间用 ；和 ，推进），像那条样例一样；
- **下面那个 11 节骨架不再是"外形"，改成"内容清单"**——段落里必须点到这六件事（顺序照旧）：
  ①人物形象（逐项外观、身份唯一）②场景与光线 ③镜头/景别/画幅/时长 ④口播·音色·口型（台词引号 + 固定句）
  ⑤动作与台词逐句绑定（手部动作 + 眼神/眉/下巴 + 语气 + 收势）⑥禁令（文字/字幕/水印/畸变/音效/旁白 + 不要什么）；
- **@ 只写一次**：每个素材在整段里只 @ 一次，后面提它就直接说"视频""图片1""那本日历"
  （样例里 @视频1/@音频1 各一次就是这个写法）。素材件数越少 @ 越少——**能拼成一张"辅助信息拼板"的
  （站位/道具/海报）就拼，但人物形象要单挂**（拼板会让它掉到 15–35% 像素，rules 20 的"去毛刺"也要求单图）；
- **骨架式（11 个小节名 + 每拍一行）仍然合法**：复杂项目、多人多段、需要逐拍对齐时用它（`═══ 版本N ═══` 分段照旧）；
- `tools\提示词体检.py` **两种形态都认**：正文里没有【】小节名时自动走"段落式"分支
  （跳过小节名/顺序/拍点那几项，改用内容覆盖 + 密度 + 台词逐字 + 负面词 + @一致来把关）。

**实测对比**（同一条素材，2026-09-18）：骨架式 正文 1958 字 / @ 出现 31 次 → 段落式 **954 字 / @ 5 次**，
体检都 0 不合格；用户认可的样例是段落式、每句 56.7 字，段落式实测 98 字/句（更密）。

### 替换类专用：**毫秒逐拍四件套**（2026-09-19，rules 第 66 条；可整段抄的句式）

替换类（换人/换物/换箱/换景）在这四条上照写，**段落式与骨架式都适用**（段落式就把它们串进同一段）：

**① 身份对应锁（放最前）**

> 先把对应关系锁死：把@视频1里那位{原片角色外观}整条替换成@图片1{新角色}，身份一一对应、**不允许互换、不允许融合、不允许出现原片人物的身份**——成片里的脸、发型、服装只能来自图片1，原片{某件具体衣物/配饰}不得混到{新角色}身上，也不得让原片那个人以任何形式再出现在画面里。

**② 形象参考边界（紧跟其后，最易漏）**

> 图片1只提供{发型、五官脸型、肤色、身体比例、服装}这几项外观，**图里{具体姿势，如"手放胸前"}的站姿、身后的{具体背景，如"绿黑板/红色横幅/木讲台"}、以及那张图本身的构图统统不要复制进画面**；@图片2只提供{道具}的外观与印刷，**那张商品图的白底、摆拍角度与投影也不要复制**。

**③ 毫秒逐拍（中间主体，每拍三段）**

> 接着按毫秒逐拍走完这 {n} 秒，节拍与切点一律照原片（原片在第 {x}ms 与 {y}ms 各切一次）：
> **0000–1600ms** *镜头是原片那个竖版低机位近景*，{新角色}{动作链：弯腰伏箱口 → 双臂上举起身 → 腾空离地 → 落回箱内消失}；**这一拍严格保持**原片人物的身体姿态、手部位置、{道具}位置、人物在画面里的大小与镜头角度，**严格复刻**原片的动作幅度、动作速度与身体重心变化，{神态落点}；
> **1600–2400ms** *画面里箱子空了、四片箱盖保持张开，镜头照原片朝箱内缓缓推进*；这一拍严格保持原片的镜头运镜、{道具}位置与画面构图；
> **2400–3780ms** *俯拍箱内，镜头继续按原片缓慢推近直到{文字/主体}的极近距离特写*；这一拍严格保持原片的镜头距离、视角、景深与推进速度。

**④ 收尾再锁一遍（放最后一句禁令之前）**

> 收尾再锁一遍：成片里自始至终只有{角色}一个人、只有这一种{道具}外观，{逐项外观，如"浅蓝色短袖T恤、短发、金丝细框眼镜"}全程不变，{上屏文字}全程不变。

**依据**：2026-09-19 B站 `BV13oYC6fE36`（UP 逢坂的大河 / MiniMax H3）评论区 UP 自发提示词原文；完整依据见 `rules.md` 第 66 条。

```
【总纲】{一句话：这条以谁为准、做什么}。

{末拍}n–{总时长}秒 {收势}
【口播·音色·口型】{谁说/什么时候说/台词逐字/音色来源/发音要点/口型同步}。
【镜头与景别】{机位、运动、构图；静止就写死「全程绝对无运镜」}。
【画面纪律】{画面里几个人、不得出现什么、画幅与时长}。
【负面】{集中列禁止项：字幕/文字/水印/Logo/BGM/音效/旁白/AI畸变/…}。
```

### 密度（2026-09-17 加：**骨架管外形，密度管"写多细"**——只守外形会写出"规格书"）

用户 2026-09-17 原话："怎么感觉少了点细节刻画，例如表情什么的，和图片这种提示词已经越差越远了"。
起因：骨架只规定小节名与顺序，**没有密度下限**，于是把一条提示词写薄了也没人拦（实测那条只有
28.6 字/句，全库最低；用户认可的 `四六级报名两本书` v7 是 56.7 字/句、神态词 15 处）。
现在把它变成可机检的事（`提示词体检.py` 的「细节密度」两项）：

- **每句均字**（只量描述性内容，`【负面】`/`【画面纪律】` 这两个禁项清单不算）：
  **口播类（有台词）≥45 字/句**、**素材/替换类（无台词）≥40 字/句** 算达标；<40/<32 会报注意/不合格。
- **每拍 40–70 字**：拍点行是细节的主要载体，写成 `0–2.9秒 站定，抬手，看向镜头；` 这种 20 字的
  骨架式句子就是"薄"。每拍要写**四层**：①手/腿的具体动作（高度、角度、幅度）②身体与重心（前倾几度、
  重心移到哪只脚、肩线）③**神态**（眼神、眼睑、眉、嘴角、下巴——有台词时必给，参 rules 第27条的情绪七项）
  ④节奏与语气（快慢、停顿、加重、收势）。
- **神态/微表情词**：**有台词却一处都没有 → 不合格**（rules 第27条）；无台词片不强制
  （素材转绘里人偶没有五官，写表情反而是错的）；密度低于"每 300 字 1 处"会提示补。
- **别为过检灌水**：密度是"把该有的层写出来"，不是加形容词堆字；不确定就对照 rules 第27条那七项。

**必写**：总纲 · 素材分工 · 主体 · 动作与时间轴 · 镜头与景别 · 画面纪律 · 负面。
**按需**：场景（无独立场景素材时也要写一句"背景由谁决定"）· 道具 · 口播·音色·口型（有台词必写；
无台词片改用【声音】写"音乐沿用原声/全片静音"）。

### 为什么是这个顺序（给模型读的线性顺序）

1. **先立"以谁为准"**（总纲 → 素材分工 → 主体/场景/道具）：参考类/替换类最容易翻的车就是
   模型把参考视频里的身份、场景、服装一起带进来（rules 第20b 条）。把分工写在**最前面**，
   等于先声夺人地划清"谁管什么"。
2. **再讲"怎么动、什么时候说什么"**（动作与时间轴 → 口播）：拍点用统一格式
   `a–b秒 …`，**每拍一行**——模型最吃这个结构，一分钟内就能对齐"第几秒做什么、说什么"。
3. **然后才是"怎么拍"**（镜头与景别）：运镜属于表现形式，放前面会跟动作抢注意力。
4. **最后集中"别做什么"**（画面纪律 + 负面）：**取消极句与正向句混排**——今天两份提示词
   都是把「不得改词」「不要推近」散在各节里，既看不出边界、也容易和正向描述打架。

### 交付格式（这一条最容易被忽略，也是"看着不像一套东西"的主因）

- `文案\提示词.txt` 与项目根 `提示词.txt`：**只有元信息 3 行 + 正文**。
  正文里**不许出现** markdown 标题（`##`）、表格（`|…|`）、分隔线（`---`）、引用块（`> `）。
- **素材清单表 / 反馈对照表 / 联网查证 / 验收清单 / 变更记录** → 一律进 `备注\备注.txt`。
  （`文案\提示词.txt` 是要**整段复制去粘贴**的，多一行表格就多一分被模型当正文读进去的风险。）
- **多版本**：主版在前，每版用 `═══ 版本N（主版/备选）· 一句话 ═══` 分隔，**每版自带「上传：」行**
  （不同版本的素材不一样时尤其重要）。
- 小节名只能用骨架里那 11 个；历史交付用过的别名（【替换】【镜头】【动作类型】【音色与语速】
  【真人质感】【画面里只有一个人】【质量与负面】…）**不再用**——内容合并进对应小节。

### 自检（出完就跑，别等用户看出来）

```bash
python tools\提示词体检.py --project "<项目目录>"      # 读 项目根\提示词.txt 或 文案\提示词.txt
python tools\提示词体检.py -i "<提示词.txt>" --json    # 机读（agent / 工作台用）
```

检查项＝元信息 3 行 · 正文不带 markdown 壳 · 必备小节齐与顺序对 · 拍点格式与时间轴连续、
末拍对齐总时长 · 有「上传：」行且点名了正文引用到的每个 @ · 图生视频不写 @视频（rules 第10条）·
台词与正文逐字一致 · 负面清单覆盖 · 不重复同一句话 · 多版本分段。
**只改格式，不为过检改内容**；有 FAIL 就改到没有为止（WARN 可留，但要看得懂为什么）。

## 0.1 模型选择（**由用户自己选**）

- **不按台词时长自动选模型**：档位以用户自己的选择为准；agent 每次出提示词**只告知本条预计需要多少秒**（字数 × 4.5–4.8 字/s 估算）。
- 只在"预计时长超过用户所选档位上限"时提醒一句（seedance 2.0 fast 输出 ≤15s、seedance 2.5 ≤30s——**截至 2026-09-14；以 `references/platforms.md`「模型与限额」表为准**），**不替用户改档**。
- 模板 B（多段分镜）与 C1b（两段式）仍为备选，仅在所选模型装不下时才用。
- **模板按分类取用**：先定分类，再取对应模板框架；下方模板是框架与示例，不是填空卷。

## 0.2 画幅：默认 9:16 竖版（rules 第26条）

> **画幅由用户在平台自行选择，提示词里的画幅句改变不了成片画幅**。本节的落点=①**交付时提醒用户"请在平台上手选画幅"**（写进四项核对；默认竖版 9:16，按需求可横屏/方屏，**不强制竖屏**——2026-09-15 用户裁定）；②横版素材要出竖版时，用它描述取景/处理方式（下两路）。

横版源片（16:9/4:3 的参考视频、原片）改竖版有两条路，**两条都必须在提示词里写清竖版怎么来**（不写就等于交给模型随手裁）：

- **路① 提示词描述取景**：人物为中心取竖条、人物在画面水平中央、完整入画、高度约占画面高 70%、不拉伸压扁、被裁掉的背景不新造场景、镜头全程静止。
- **路② 本地预转竖版再上传**（最稳）：先用工具转，输入输出画幅一致，模型不再重构图。


```
以@图片1（原片关键帧）为准：人物站位、镜头角度、背景环境、画面构图全部保留；
只把人物造型换成：{服装/发型/妆造/表演状态，统一往 {风格} 靠}；
不要改变背景，不要改变镜头角度，不要新增人物或道具；画面里不要出现任何文字。
```

### D3 逐段口型 / 表演（视频模型；每段 = 一张图 + 一段音频）

```
以@图片1为唯一画面来源，人物与@图片1完全一致，只允许自然演唱口型与轻微表情变化；
口型与@音频1逐字同步；固定机位，全程绝对无运镜；9:16竖屏；
不要有任何字幕；不要出现任何文字（不要生成水印，不要生成Logo）；无AI畸变。
```

### 要点

- **切段 = 原片镜头切点**，一句或两句一段（rules 34）；段短 → 口型更稳、单段砸了可单独重做。
- **歌词/台词一字不改**，模型只负责作曲与分角色演唱（rules 35）；不要写新剧情。
- 动手前先列**保留/替换清单**（rules 36）：站位、镜头、背景、台词原句=保留；服装、发型、妆造、表演状态、曲风=替换。
- 装配：逐段生成口型 → 接回时间线 → **字幕在后期加**（不写进生成提示词）。
- 光影不统一时走「全景空镜 + 局部重绘」（rules 37，待验证）。

## 模板 E：分段多提示词框架（长视频 / 多主体替换）

**什么时候用**：一条片子**超过平台单次生成时长**，或**每段都要做多主体替换**——**不要**为凑"单主体"把片子切成 2–3 秒的碎块（会把素材与逻辑切乱），而是：

**切法三条**：
1. **按"大场景变化的转场"切**（背景/机位整体切换处）——不是等长、也不按主体在场隔离；切完每段自然落在平台单次生成的时长内（实例：9.0/9.15/2.9/10.05s）。大场景转场用**粗窗聚类**找（0.5–1s 窗签名 + KMeans，工具里对应 `成片拆解.py --scene`），细粒度硬切点用 `tools\成片拆解.py`（用于段内校对）；
2. **段短于模型最短输出（4s）**：按最短值生成、后期掐短，或与相邻段合并重切；
3. **缺量补料**：某段明显偏短时，补一段**同角色**的镜头凑够（补料段的主体要单独标注，见框架里的【分段提示】）。

**素材口径**：**每段挂全套角色素材**（视频 + 站位图 + 该段出现的每个主体的角色图）——分段不代表把主体拆开；实测（红白模四段）每段都是红+白同场。

**框架（一个项目一组提示词，逐段一块）**：

```
【段1】{时长}（源区间 {a}–{b}s）——素材：视频1_段1 + 站位图 + 图片1~N
【本段要替换的主体】{红：1 个→@图片1；白：M 个→@图片2~@图片N}。注意：{开头 X 秒只有红色人形 ……}
【站位与角色】{红→@图片1 的锚定句；白→@图片2~N 按站位图从左到右一一对应；同一人穿不同服装时写明"脸型发型一致、只有服装不同"}
【分段提示】{该段特有的时间/主体变化，例：8.5 秒之后只有红色人形，不要凭空生成白色人形}
【排除】同一角色不得重复出现两遍；不要出现第三类人；不要新增人物。
【表情与动作必须跟着原片】…（原片直投替换框架的四段，见 playbooks.md 第一部分）
【锁定】镜头/构图/位置/节奏/背景/光影不变；无文字水印；静音；时长一致。

【段2】…（同样结构；只改【本段主体】【分段提示】与素材名）

【段3】…
```

**要点**：
- **每段的【本段主体】与【分段提示】都要改**——这是分段版最容易漏的地方（段内主体与素材必须一一对应）；
- 段时长低于模型最短输出（4s）时：**按最短值生成、后期掐短**，或与相邻段合并重切；
- 生成顺序：**最短/最简单的段先跑**，多主体段最后跑；
- 拼接前先按"段序"核对每段的**实际时长**，接缝处前后各掐 0.2s。

## 模板 F：文生视频（纯文字，无任何素材）

> ⚠️ **未验证：本机暂无文生视频样本**。以下框架按"无锚定 → 全部靠文字描述"的原理推写，第一条真实需求进来后补样本并转正。

**适用**：用户什么素材都不给，只给一段文字（或一句需求），要一条视频。**不引用任何 @图片/@视频/@音频**（引用一致性：没上传的不能写，rules 第10条）。

**为什么难**：没有图片锚定，人物长相、场景、风格全靠文字，**跨段一致性只能靠描述词逐字复用**（rules 第2条的做法在这里从"辅助"变成"唯一手段"）。

### 框架（六节；分节名可合并，内容不可省）

```
【风格】{一句话定体裁与质感}，{画幅}，{时长}。
【人物】{性别+年龄段+发型发色+脸型/五官特征+服装材质颜色}，{体态与气质}。
【场景】{地点+时间+天气+环境元素}，{光线方向与色调}，{画面纵深与前后景}。
【动作】{逐句/逐段动作：先做什么、再做什么、以什么姿态收尾}，动作连贯、有起点有收势。
【镜头】固定机位/景别（{远景/中景/近景}），全程绝对无运镜，人物在画面中的大小与位置自始至终不变。
【负面】不要有任何字幕，不要出现任何文字（不要生成水印，不要生成Logo），无AI畸变，不要新增未描述的人物或道具。
```

### 结构公式（社区口径，2026-09-14 抖音调研）

抖音同类教程的一致公式，可与上面的六节框架对照使用：

- **基础版**：`主体（细节）+ 动作（明确）+ 场景（背景）`
- **进阶版**：`[运镜/景别] + 主体+动作 + 场景 + 光影 + 风格 + [时长/帧率/音效]`
- 叙事示例：`推近镜头 + 20岁亚洲女孩白裙旋转 + 阳光公园 + 黄昏侧逆光 + 日系清新风格 + 5秒/24fps/轻柔钢琴音`
- 产品示例：`特写镜头 + 手机旋转展示 + 纯白背景 + 柔光 + 极简风格 + 8秒`

**五条技巧**：

1. **细节具象化**：用「20 岁亚洲女孩白裙」替代「女孩」，「海浪拍岸 + 橙粉晚霞」替代「海滩」；动词用「缓缓飘落」「快速奔跑」控节奏，避免「跳舞」「走路」这类模糊表述。
2. **镜头语言**：运镜（平移 / 推近 / 无人机航拍）+ 景别（大全景 / 近景 / 鸟瞰）+ 视角（跟随 / 鱼眼）。
3. **光影氛围**：「黄昏侧逆光 + 金色光晕」「冷色调霓虹雨夜」，避免「很亮」「很美」等虚词。
4. **风格明确**：「皮克斯动画（色彩鲜艳 / 夸张比例）」「赛博朋克（霓虹灯 / 雨夜）」，拒绝「好看」「卡通」。
5. **基础规范**：肯定句（不用疑问句）、无矛盾（别写「阳光雨夜」）、无选择（「红裙」而非「红或黑」）、**关键词重复**（同一元素在运镜与场景里重复强化）。

**避坑**：逻辑冲突（「结冰湖面 + 游泳」）、信息过载（10 秒内只讲一个核心动作）、纯静态描述（要加「眨眼」「挥手」等动态）；**先用 5–8 秒短时长测试再扩展**；参数 1080P/24fps 偏电影感，30fps 通用。

**写法要点（四条）**：

1. **描述词逐字复用**：多段/多镜头时，人物句与场景句必须**逐字复用**，任何措辞变化都会让人物漂移（rules 第2条）。
2. **抽象词翻译成画面**：模型渲染不了"很有氛围""高级感"——要落成**物、动作、光**（"暖黄台灯光从右侧打来，桌面有一杯冒热气的水"）。
3. **一镜一动作**：单段只写一个连续动作，不要在一段里塞多个场景切换（要切换就分段，见模板 B）。
4. **负面词每段写死**（rules 第1条）：不要有任何字幕 / 全程绝对无运镜 / 无AI畸变；文生视频尤其容易"自己长文字"，结尾再单独成句 `不要生成水印，不要生成Logo。`（rules 第29条）。

### 完整示例（**未验证，仅示范格式**）

```
【风格】写实纪录片质感，9:16竖屏，约10秒。
【人物】一名三十岁上下的男性教师，短黑发、戴细框眼镜，穿浅灰色棉质衬衫，体态清瘦、站姿放松。
【场景】晚间的书房，木色书桌、台灯与一摞书，窗外深蓝色夜空；暖黄灯光从画面右侧打来。
【动作】他先低头翻一页书，随后抬头望向镜头，手指轻点书面，最后双手合拢放到桌面上收势。
【镜头】固定中景，全程绝对无运镜，人物在画面中的大小与位置自始至终不变。
【负面】不要有任何字幕，不要出现任何文字，无AI畸变，不要新增未描述的人物或道具。
不要生成水印，不要生成Logo。
```
