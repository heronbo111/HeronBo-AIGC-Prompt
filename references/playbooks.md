# 实战手册（替换类 / 二创拆解 / 深度视频与环境准备）

三部分：**一、替换类手册**（L1–L4 分级、工具选型、流水线、失败点）；**二、二创拆解手册**（机器证据 → 读片三问 → 拆解报告 → 复现路线）；**三、深度视频与环境准备**。
规则正文见 `references/rules.md`；模型与限额见 `references/platforms.md`。

**难度分级速记**：L1＝物件替换（商品/道具拟人化，没人物的属性）；L2＝台词替换（人物场景全保留，只换口播内容）；L3＝同人造型替换（同一真人换装/换手中物）；L4＝人物替换进原片（换人并复刻原片动作/镜头/场景）。

# 一、替换类手册（人物/物件替换进既有画面）

## 1.1 难易度分级（基于实测）

| 级别 | 任务 | 实例 | 结论 |
|---|---|---|---|
| **L1 物件替换** | 商品/道具替换，无人物属性（拟人化） | 考研真题拟人化替换果冻原片 | ✅ C1 拟人化配方 2/2 成功（视频锚定+商品图替换唯一主角+Q弹+原声+背景色迁移） |
| **L2 台词替换** | 人物/场景全保留，只换口播内容 | 样本4（两本书）、样本6（背单词） | ✅ 参考视频+音色参考+台词引号，"完美/很不错" |
| **L3 同人造型替换** | 同一真人换装/换手中物件 | 三本书（黑上衣+三本新封面） | ⚠️ 两步法（rules 23）：图片层 image2image 做替换 → 视频层零替换；视频层直接替换不可靠 |
| **L4 人物替换进原片** | 换人 + 复刻原片动作/镜头/场景 | 示例-直播空降、示例-影视替换、示例-中国人能飞 | ❌ 通用视频模型不可行（锚定压制替换/身份漂移/节奏不卡）→ 专用动作迁移工具或替代方向（见下） |

**核心原则（rules 23）**：内容替换交给图片模型，视频模型只做"动起来"；L4 用专用动作迁移模型，不用通用视频生成硬顶。

## 1.2 L4 推荐路线

### 首选：平台内 —— 把驱动视频转成「深度视频」做信息过滤，再让视频模型换人（零额外付费）

- **针对问题**：rules 20b「参考视频锚定会压制替换指令」——原片自带脸、服装、背景、灯光与整体风格，模型会一起照抄，替换句失效。
- **做法**：把驱动视频**转成黑白深度视频**（只保留人物动作姿态与前后空间关系），**按 15 秒以内切分**，当 @视频1 用；再配 **人物图（只管角色）＋ 场景图（只管环境）**。
- **提示词写法**（逐项锁定 ＋ 反向排除，缺一不可）：

  ```
  @视频1 只参考动作、动作顺序、节奏、身体幅度和姿态变化，
  不要参考它的黑白画面、人物身份和原始场景；
  人物严格参考@图1（面部、发型、服装）；环境严格参考@图2。
  ```

- **适用**：舞蹈、走秀、武术、人物表演等"对动作节奏要求高"的复刻；也适合"复刻动作但换人换环境"。
- **画幅（rules 第26条）**：替换类默认**交付 9:16 竖版**；横版驱动视频先用 `python tools\竖版画布.py -i "<横版原片>"`（默认 crop 满屏竖版、只裁左右且人脸自动定位；`--mode pad` 走不裁切的竖版画布）转成竖版再进去。平台「智能编辑 / 全能参考」的画幅跟随提交设置，**提交时手选 9:16**。**本机例外**：`rules.local.md` L10 对替换类驱动片裁定"不再转竖版、按源片比例提交"，冲突时从其规定。
- **依据**：第三方教程《Seedance新玩法》（原文与两段示例提示词见 `${SAMPLES_ROOT}\_范本调研_2026-09-11\第三方教程_Seedance深度视频换人法.md`）＋ rules 第30条。博主只展示效果，本机未实测，故标待验证。

### 中间态：人物遮罩片（2026-09-11）

用 `tools\人物遮罩.py` 把**人物区域糊掉、场景保持清晰**（实测 `--check` 7/7 时间点 0 人脸，场景区清晰度 82.8、人物区 14.6）。
深度片把场景/光线/机位一起丢了，原片又把身份锁死；**遮罩片只去掉"人物长什么样"**，是这条路线目前最均衡的输入——配"目标图"当 @图片1 用（提示词写法见样本库 `中国人能飞替换\文案\提示词_模糊片路线_v1.txt`）。

**前置能力（2026-09-11 已建）**：本机已具备"转黑白深度视频"能力——`tools\深度视频.py` + Depth-Anything-V2-Small ONNX（模型放本机缓存，不进仓库），实测 1.97 帧/秒。安装与用法见本文件第三部分。**顺序：先 `竖版画布.py` 转竖版，再转深度。**

## 1.3 通用失败模式（迁移类通病）

1. 遮挡与手部交互（手持物、自遮挡、侧脸）是最大失败点
2. 身份漂移：长片 5–8s 后相似度下降 → 控制在 5–10s 或分段+身份锁定
3. 打光/色调不一致 → 选带 Relighting 的方案（Wan-Animate-2）
4. 相机/背景保留大多数产品不承诺（Kling/即梦会重绘场景）
5. 输入限制：单人正面、脸无遮挡、2–30s、<200MB、720p 档 25fps
6. 厂商指标（>95% 微表情保真等）是营销口径，未见独立评测
7. **横版源片直接要竖版输出 = 模型替你重构图**（人物放大 2–3 倍、构图改变）：先把源片转竖版输入再要求"不裁切不放大"（rules 第26条 + `tools\竖版画布.py`），不可依赖提示词让模型保留横版构图

## 1.4 合规

- 替换真人脸/声音需本人书面授权；深度合成内容需标注 AI 生成（生成式AI/深度合成管理规定）
- 影视片段替换过审难、审核规避处理代价大（rules 第7条）——**优先自拍原片做驱动视频**

## 1.5 MV / 音乐二创类换人替换（两组拆解实测 + 第三方作者配方；本机未端到端跑通，待验证）

**形态**：一条 MV / 音乐短片，保留歌、编舞、场景、机位与**剪辑点**，只把人物层换成目标角色（rules 第36条）。两组实测均证实这是当前爆款二创的主流做法：
- `参考1–4`（真人歌舞片 → 红白模/女版/希特勒三版）：剪辑点与原片 7.73/11.5/14.9s 三处重合 ±0.5s；
- `《琵琶曲》系列`（3D 动画 → 动漫/meme/生化/战术四版）：25–35 个镜头同序重绘；其中 3 条共用**同曲不同录音版**音轨（rules 第35条 路线③）。

**六步流程（路线 A，主推）**：
1. `tools\成片拆解.py -i "<原片>" --asr` 出**切点表**（= 切段表）；
2. 定声音路线（rules 第35条 四选一；可用 `tools\成片对比.py -a "<同款二创>" -b "<原片>"` 反查别人走的哪条）；
3. **剪映预处理**：按切点切段（每段 2–8s）→ **单人物化**（作者原话："我怕生成出来角色错误，我剪映剪了一下，只有一个人物"）→ 字幕/水印用大黑块盖住 → 段文件带时间码；
4. 逐段替换生成（输入=该段视频，必要时 + 目标角色图），提示词用下面的骨架；
5. 每段**抽 2–4 张**，按段质检（形象 / 表情时机 / 形变保留 / 单人物 / 无文字 / 时长 / 镜头），通过即锁定，废段单独重跑；
6. 剪映接回时间线 → 响度统一 → 机器复核（`成片拆解.py` 查多出人物/文字；`成片对比.py` 查画面是否同轴）。

**提示词骨架（"原片直投替换"版；第三方作者实测口径 + 本 skill 锁定句）**：

```
【替换】画面中的人物替换为{目标角色}，与@图片1完全一致（面部、发型、服装、体型比例）。
【表情同步】角色必须完全模仿原视频人物的全部动作和表情，尤其是表情变化必须完全同步保留：
原视频人物出现什么表情（惊讶、震惊、害怕、愤怒、开心等），替换后的角色都必须做出完全相同的表情、表情变化和变化时机。
【动作与形变】完整保留原视频中的所有动作效果和身体变化，包括夸张动作、弹性效果、身体拉伸、胳膊拉长、身体变形等；
原视频人物身体如何运动、拉伸、变形，替换后的角色必须完全按照原视频同步模仿，不恢复成正常人体动作。
【锁定】除人物（和{道具}）外，镜头、运镜、构图、人物位置、动作节奏、体型比例、背景、光影全部保持不变。
【单人物】画面中不得出现原片其他人物、不得新增任何人物。
【无文字】画面无任何文字、字幕、水印；被遮挡的字幕区域用与周围一致的正常画面自然补全。
【声音】{沿用原片原声，不重新配乐 / 保持静音}；【时长】与输入视频等长。
不要生成水印，不要生成Logo。
```

> **与 rules 第32条（替换类宜短）的关系**：短版（分工三句 + 锁定句）适用于"素材分工明确"的路线（深度片 / 遮罩片 / 图层面替换）；本骨架较长，是因为**原片直投**时模型必须被显式约束"表情与形变跟着原片走"，否则会自创表演。两版并存，按输入形态选。

**抽卡经济学（对治"整片一次替换、抽 50 次成功 1–2 次"）**：
- 整片一次替换的失败**不可定位**；分段后单段独立抽卡，废段只重跑该段；
- 失败归因判据：**每次失败原因不同**（形象漂 / 多人物 / 出文字）→ 模型波动，继续抽有效；**每次失败原因相同**（始终替换不动）→ 输入或提示词有结构性问题，**换路线（图层面替换 / 遮罩片）而不是继续烧积分**。

**依据**：①B站 `BV1kuKE66Eds` 四步流程（拆分→按镜头切段→只改人物→逐段生成接回）；②本机两组拆解实测（`AI视频素材\参考1-4_二创拆解对比.md`、`AI视频素材\琵琶曲拆解\琵琶曲_二创拆解对比.md`）；③第三方作者「雨霖下雨了」提示词原文与"剪映只留一个人物"做法（`${SAMPLES_ROOT}\_范本调研_2026-09-12\第三方作者提示词_雨霖下雨了_MV换人.md`）。

# 二、AI 二创拆解手册（拿到一条成片 → 机器证据 → 读片三问 → 拆解报告 → 复现路线）

> 规则编号见 `rules.md` 第33–38 条。配套工具：`tools\成片拆解.py`（只出证据，不下结论）、`tools\成片对比.py`（二创 vs 原片）。

## 2.0 什么时候用

- 收到一条 AI 二创 / 爆款成片，诉求是"拆解 / 仿做 / 复现 / 看看这是怎么做的 / 我发你几段 AI 二创，你试着拆"。
- 不适用：直接给文案+素材要提示词 → 走 `SKILL.md` 工作流 1（分类）。

## 2.1 边界（先说清不做什么）

- **拆解 ≠ 复现授权**：先出拆解报告，再问"要不要按哪条路线复现"；**不代提交生成**（rules 13 + 工作区铁律）。
- **版权**：影视原片复刻卡版权审核（rules 7）；别人的成片只作分析对象，其素材能否直接当驱动片要用户确认。
- **证据分级**：机器证据（本机实测）／视频作者口径（第三方，未经我们实测）分开标注，别把后者写成规律。

## 2.2 三步流程

### 第一步 · 机器证据

**读片方式优先级（能不下就不下）**：

| 优先 | 方式 | 能拿到什么 | 注意 |
|---|---|---|---|
| ① | **对方直接发文件**（最省事、最准） | 全量：帧、音轨、字幕位置 | 拆解首选；让用户把 mp4 拖进来即可 |
| ② | **不下载**：平台接口 / 页面文本 | 标题、简介、时长、画幅、作者自述的方法要点；有时能拿字幕列表 | 实测（B站）：`api.bilibili.com/x/web-interface/view?bvid=<BV>` 可拿标题/简介/时长/画幅；`x/player/v2` 的字幕在 `need_login_subtitle:true` 时**拿不到**（不代登录）；页面 HTML 常被验证码挡住。**只拿到文字元信息时，不要当"已经看过视频"，直接说拿不到画面** |
| ③ | **下载后本地读**（兜底，但有据） | 逐帧画面 + 音轨 + 转写 | `tools\下载B站成片.py` → ffmpeg 抽帧/OCR/看图 + `faster-whisper` 转写 → 机器证据 |

> 铁律：**能不下就不下**；②拿不到画面就**明说拿不到并停下**（别靠简介硬编拆解）；③下载的成片只作分析对象，**不得当素材再上传生成**（版权，rules 7）。

拿到的是**链接**时（走③）先落本地（拆解工具吃本地文件）：

```
python tools\下载B站成片.py "<链接或BV号>" --out "<素材目录>"
```

> 只取匿名可达清晰度（通常 480P，拆解看结构够用）；**下载的成片只作分析对象**，不要再上传去生成（版权，rules 7）。

本地文件直接跑：

```
python tools\成片拆解.py -i "<成片>" --asr
```

**有原片可比时**（二创 vs 原片）再多跑一步——省掉肉眼听音判断：

```
python tools\成片对比.py -a "<二创>" -b "<原片>"
```

输出两行结论：**画面**是否同时间轴（序列相关 + 最佳滞后）、**声音**走哪条路线（原声照搬 / 保伴奏换人声 / 整曲重制）。

报告出到源片旁：`<成片>_拆解报告.md` / `.json`。看四类证据：

| 问题 | 报告里看什么 | 判读 |
|---|---|---|
| 节奏跟不跟音乐走？ | 切点与节拍对齐率、平均镜头长 | 对齐率高 + 镜头长 0.5–2.5s → 音乐驱动 → **声音先行** |
| 是不是多短段拼接？ | 镜头数、平均镜头长、段内人脸位移 | 镜头多而短、人物位移小 → 每段一张关键帧 |
| 口型是不是逐段配？ | 转写段边界 vs 切点时间 | 边界与切点同拍 → 音频提前切好；仍需抽帧复核 |
| 有没有声音可用？ | 音轨状态 | `静音轨` → 仅可当无声驱动片；有能量但无词 → 纯音乐/BGM |

> 变化候选点表（算法眼中变化最大的 5 个点）用来对照"硬切/闪黑/大动作"，算法没到阈值的点也在表里，人工复核。**要"大场景块"切段依据时补跑 `--scene`**（0.5s 窗聚类，输出块边界）。

### 第二步 · 读片三问（rules 33）→ 定形态

三问结论 + 证据写进报告。形态四选一：

| 形态 | 特征 | 后续走哪 |
|---|---|---|
| 口播驱动 | 有人声台词、镜头长、节奏跟语气 | rules 17 配方（本系列主路） |
| 音乐驱动 | 跟唱口型、切点卡节拍、转写成句成歌 | 本手册 2.4 节（rules 33–36） |
| 动作驱动 | 舞蹈/运动、无台词或纯 BGM | rules 30/32（深度视频 + 素材分工） |
| 替换驱动 | 画面保留原片、主体被换 | rules 20–24（L1–L4 分级） |

### 第三步 · 出《拆解报告》（模板，可直接复制）

```
【拆解报告】<片名 / 链接>
一、一句话定位：原片/梗 + 新世界观或新风格 + 音乐形态
二、驱动源判定（口播/音乐/动作/替换）：结论 + 证据（切点数、对齐率、转写、人脸位移）
```

## 2.4 音乐二创复现配方（照视频四步；待成片验证）

1. **拆声音**：原视频与音频拆开；台词按角色与顺序整理，**中文一句不改**（rules 35）。
2. **做歌**：风格词（如"迪士尼王子公主音乐剧感"）+「**旋律贴合声调**」+ 分角色演唱 + 冲突跟着原剧情往上走。
3. **切段做关键帧**：歌出来后按**原片镜头**切 1–2 句一段（rules 34）；截原片关键画面，人物站位/镜头角度/背景保留，**只换人物造型**（rules 36）。
4. **逐段配口型**：每张图 + 对应音频段生成口型与表演 → 接回时间线 → 补字幕；光影不贴走「全景空镜 + 局部重绘」（rules 37，待验证）。

## 2.5 常见误判

- 把"参考视频锚定"当万能：锚定会**压制替换指令**（rules 20b），拆出"保留即目标"的片子别硬套替换类写法。
- 把静音当"没声音"：静音轨片子照样可以是**无声驱动片**（替换类的干净输入）。
- 只看单帧判形态：形态要看跨段证据（位移/切点/响度），单帧看不出"逐段配口型"。
- 直接拿别人片子的素材开工：版权与授权先问用户（rules 7）。

## 3.2 模型下载（换机时重建，两条路）

1. `ffprobe` 输出的宽高/帧率/时长与源片一致、**无音轨**；
2. 抽一帧看 R≈G≈B（**是灰度**）；
3. **人物区域（画面中心带）比背景（四周/顶部带）亮**——本机实测：中心带 152.1 vs 顶部带 5.2；
4. 用 `tools\识别工具\ocr.ps1` 抽帧 OCR 应为**无文字**（深度图没有文字信息）。

## 3.8 配套工具：人物遮罩（`tools\人物遮罩.py`，2026-09-11 建并实测）

**用途**：把参考视频里**人物区域糊掉、场景保持清晰**，做出"只去掉人物外观、保留动作/光线/机位"的驱动片。
它是"深度片（丢场景）"与"原片（锁死身份）"之间的**中间态**——L4 换人时用它当 @视频1，身份锚定与场景丢失两个问题一起规避。

```bash
PY="C:/Users/<用户名>/AppData/Local/Programs/Python/Python312/python.exe"
S="C:/Users/<用户名>/.zcode/skills/HeronBo-AIGC-Prompt"

# 先出深度片（做掩膜用），再出遮罩片
"$PY" "$S/tools/深度视频.py" -i "<源片>" --max-frames 30          # 可选：先短测
"$PY" "$S/tools/人物遮罩.py" -i "<源片>" --depth "<源片>_depth.mp4"     # 输出 <源片>_masked.mp4
"$PY" "$S/tools/人物遮罩.py" -i "<源片>" --depth "<...>" --mode solid    # 涂纯色块（不推荐，易被模型画出来）
"$PY" "$S/tools/人物遮罩.py" --check "<遮罩片>" --ref "<源片>"           # 只验收
```

- **掩膜怎么来**：深度片 Otsu 近/远分割 → 最大连通域 → 膨胀；**再并上 YuNet 人脸框加固**（外扩 1.6 倍，保证脸一定被糊）；`--band 0.815,0.915` 默认把底部字幕带一起糊。
- **性能**：与深度片同量级（无推理，仅模糊+编码）——本机 1080×1920 / 412 帧约 **2.5 分钟**。
- **验收（`--check` 自动跑）**：抽 7 个时间点检人脸 + 比对脸区清晰度。**本机实测**：7/7 时间点身份已去除（其中 1 个是模糊块误检：清晰度 3.0 vs 原片 21.9），场景区清晰度 82.8（人物区 14.6）。
- **依赖约束（已处理）**：opencv 的 ONNX 读取**不支持非 ASCII 路径**，而本仓库路径含"识别工具"中文目录 → 工具会先把模型拷到 `%TEMP%\yunet_tool.onnx` 再加载（`tools\竖版画布.py` 也是同一处理）。**自己写脚本时记得同样处理**。
- **边界**：同样只做本地预处理，不提交任何平台、不消耗积分。
